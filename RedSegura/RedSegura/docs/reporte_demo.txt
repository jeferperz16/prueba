Q1 - Buscar "Hospital Universitario" en el ABB y en el AVL
==============================================================================

Inserción en orden del dataset (S01..S12) - 12 claves
  ABB: encontrado     pasos =  3   altura = 7
  AVL: encontrado     pasos =  1   altura = 4
  -> El AVL necesitó 2 paso(s) menos.

Inserción en orden alfabético ascendente (peor caso del ABB) - 12 claves
  ABB: encontrado     pasos =  5   altura = 12
  AVL: encontrado     pasos =  4   altura = 4
  -> El AVL necesitó 1 paso(s) menos.

Lectura: la forma del ABB depende del orden de llegada de las claves (su altura va de
~log n hasta n; con entrada ordenada degenera en una lista y buscar cuesta O(n)).
El AVL se reequilibra con rotaciones y conserva altura O(log n) sin importar el orden.

Q4 - BFS y DFS desde S02 (UAJS Sede E)
==============================================================================
BFS (cola, por niveles):
  Orden : [S02, S01, S06, S07, S09, S05, S08, S10, S12, S03, S04, S11]
  Niveles:
    nivel 0: [S02]
    nivel 1: [S01, S06]
    nivel 2: [S07, S09, S05]
    nivel 3: [S08, S10, S12, S03]
    nivel 4: [S04]
    nivel 5: [S11]
  Árbol BFS (hijo <- padre): {S01=S02, S06=S02, S07=S01, S09=S01, S05=S06, S08=S07, S10=S09, S12=S09, S03=S09, S04=S12, S11=S04}
DFS recursivo:
  Orden : [S02, S01, S07, S09, S05, S10, S08, S12, S03, S04, S11, S06]
  Árbol DFS (hijo <- padre): {S01=S02, S07=S01, S09=S07, S05=S09, S10=S09, S08=S10, S12=S09, S03=S12, S04=S12, S11=S04, S06=S02}
DFS iterativo (pila): [S02, S01, S07, S09, S05, S10, S08, S12, S03, S04, S11, S06]  (igual al recursivo)

Los órdenes empiezan a diferir en la posición 3: BFS visita S06 y DFS visita S07.
Por qué pueden diferir: BFS usa una cola FIFO y agota todos los vecinos de un nivel antes de
bajar; DFS se hunde por el primer vecino hasta quedarse sin salidas y entonces retrocede.
Además, el orden entre hermanos depende del orden en que se registraron las conexiones, y
los arcos dirigidos limitan qué vértices se alcanzan desde el origen.

ANÁLISIS DE COMPLEJIDAD (n = claves, V = vértices, E = conexiones, h = altura)
--------------------------------------------------------------------------------
Componente / operación                    Tiempo                 Espacio extra
ABB insert / search / delete              O(h): O(log n) prom.,   O(1) iterativo
                                          O(n) peor caso          (delete: O(h) pila)
ABB recorridos (in/pre/post)              O(n)                    O(h) pila + O(n) lista
AVL insert / search / delete              O(log n) peor caso      O(log n) pila
AVL rotaciones LL/RR/LR/RL                O(1) cada una           O(1)
AVL recorridos                            O(n)                    O(log n) pila + O(n)
Grafo addVertex / addEdge                 O(1) amortizado         O(1)
Grafo neighbors(v)                        O(d(v))                 O(d(v))
Lista de adyacencia                       O(V + E)                O(V + E)
Matriz de adyacencia                      O(V² + E)               O(V²)
Matriz de incidencia                      O(V·E)                  O(V·E)
BFS (cola + visitados)                    O(V + E)                O(V)
DFS recursivo / iterativo                 O(V + E)                O(V) (pila)
Detección de ciclos                       O(V + E)                O(V)
Componentes débiles                       O(V + E)                O(V)
Dijkstra con PriorityQueue                O((V + E) log V)        O(V + E)
Reconstrucción del camino                 O(V)                    O(V)

Notas:
- El ABB se degrada a O(n) con inserciones ordenadas; el AVL garantiza altura
  <= 1.44 log2(n + 2), por eso mantiene O(log n) siempre (ver Q1).
- Con V = 12 y E = 18 las diferencias son pequeñas; el análisis aplica al crecer el mapa.
- Dijkstra usa eliminación perezosa de entradas obsoletas, por lo que la cola puede
  tener hasta O(E) entradas; log E = O(log V) porque E <= V².
